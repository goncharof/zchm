# Состояние проекта

Обновлено: 2026-10-17 (седьмая итерация: защита сервера, длинные партии, трофеи после боя).

## Что работает

**Данные** (конвейер из оцифрованной коробки, см. `docs/ARCHITECTURE.md`)
- Бестиарий: 97 статей с рисунками, многоголовые (огр, гидра), нестандартные атаки («смерть», «магия», «нет»).
- Книга Жизни: 15 глав, 647 параграфов; 277 из них разбиты на сцену и 399 веток решений (`tools/segment.py`).
  Подсказки к сцене, веткам и вариантам броска: удача, монстры и их число, находки и цены, бутылки, свитки,
  артефакты, таверны, лавки.
- Карта мира (20 узлов, 23 дороги), правила (классы, оружие, доспехи, вещи, 18 артефактов, 91 заклинание),
  Книга Сумерек.

**Движок**
- Персонажи 5 классов, уровни 0–12 с особенностями 12 уровня, экипировка с ограничениями класса и рук
  (и для артефактов), стрелы и метательное оружие с подбором после победы.
- Трофеи после боя: оружие и доспехи убитых врагов по описаниям Бестиария, шкуры и орочьи ятаганы на продажу.
- Бой по Инструкции: дистанция → инициатива → раунды, храбрость, особые атаки, бегство, статусы с полной
  длительностью, опыт за урон (в том числе со временем), запасная кнопка «Закончить ход героев».
- Союзники: призванные существа, иллюзии, двойники, зомби и очарованные монстры (могут выйти из-под контроля),
  спутники партии на N боёв. Магия монстров с учётом невидимости, щитов, неуязвимости и отражения.
- 91 заклинание: 80 отыгрываются автоматически, 11 информационных и ролевых — вручную по описанию.
- Финальная дуэль с Чёрным магом; победа фиксируется.

**Приложение**
- Экраны: главная (продолжить, быстрый старт, слоты, журнал), партия, лавка и трактир, карта с маршрутом,
  локация (сцена и ветки, бросок по списку, действия по тексту), бой, бестиарий с фильтрами, заклинания,
  правила, предыстория, об игре.
- Автосохранение с миграцией, три слота, экспорт/импорт, режим ведущего, лоток кубиков, автоход монстров,
  портреты героев, вёрстка для телефона, установка как приложение и игра без сети.

**Сетевая игра** (см. `docs/DECISIONS.md`, «Сетевая игра командой и ИИ-ведущий»)
- Сервер `server/` (Node.js, socket.io): комнаты по коду, вход по токену и возврат после обрыва, права на
  команды (свой герой / партия / ведущий / хозяин), чат, сохранение комнат в `data/rooms/`, раздача фронтенда.
- Режимы ведущего: ИИ (цепочка моделей: бесплатные облачные через OpenAI-совместимый API, Claude по ключу; если не ответил никто — сценарный ведущий), сценарный ведущий без ИИ (кнопки-варианты по разметке книги), живой ведущий (хозяин видит текст книги и правит вручную), без ведущего.
- ИИ-ведущий: 14 инструментов движка, стриминг реплик, кэширование, резервная модель при отказе, откат хода
  при ошибке API, снимок состояния партии на каждом ходу. Ход идёт за ходом; реплики во время ответа копятся.
  Длинная партия: когда история Claude разрастается, разговор начинается заново с краткого содержания.
- Защита сервера: проверка всех входящих сообщений схемами, ограничение частоты (реплики ведущему — 4 в минуту
  на игрока, они расходуют квоты моделей).
- Интерфейс: «Игра по сети» на главной, экран «Стол» (чат с ведущим, партия, план), «Взять героя», в бою
  ходят только свои герои, при ИИ-ведущем текст книги скрыт и номер на плане — реплика ведущему.
- Продакшен одним процессом (`pnpm build && pnpm build:server && pnpm start`), Dockerfile.

**Проверки**
- `pnpm test` — 84 теста, в том числе сетевая игра на настоящих сокетах (`tests/server.test.ts`), цикл

  моделей и OpenAI-совместимый адаптер на поддельном потоке (`tests/providers.test.ts`): движок, стор, целостность данных (`tests/data.test.ts`), фазз-тест боя против всего бестиария (`tests/fuzz.test.ts`), регрессии по итогам
  независимого ревью движка (`tests/regressions.test.ts`), сквозной прогон экранов в jsdom (`tests/app.test.ts`).
- `node tools/qa/screens.mjs` — проход по игре в Chrome на 1280 и 390 px со скриншотами и отчётом об ошибках
  консоли, HTTP-ошибках и горизонтальной прокрутке; `node tools/qa/offline.mjs` — игра без сети.
  Последние прогоны — без замечаний.
- `node tools/qa/online.mjs` с `pnpm server` без ключей (сценарный ведущий) или с `tools/qa/fake-gm-server.ts`
  (демо-«ИИ») — два игрока: вход по коду, «Взять героя», вход в локацию, сцена с кнопками, проверка удачи,
  ветка; текст книги гостю не виден. Без замечаний.

**Не проверено**
- **Живые модели**: на машине разработки нет ключей (ни Claude, ни бесплатных провайдеров), поэтому ИИ-ведущий
  проверен только на имитациях. Первый прогон бесплатно: получить ключ Groq или Gemini (AI Studio), запустить
  `GROQ_API_KEY=... pnpm server`; если модель по умолчанию недоступна, указать актуальную в `GROQ_MODEL`.
  Для Claude: Первый реальный прогон: `ANTHROPIC_API_KEY=... pnpm server` + `pnpm dev`, комната с
  ИИ-ведущим, пара ходов; смотреть в консоли сервера строки `[ИИ-ведущий …]` — расход токенов и попадание в кэш
  (`из кэша` должно расти со второго запроса).
- Dockerfile не собирался (демон Docker на машине не запущен).

## Известные упрощения
- Если у монстра несколько видов особых атак, используется первая.
- Монстры колдуют только боевые заклинания (урон и контроль).
- Вручную: Чувство зла, Чтение эмоций, Чтение силы, Обаяние, Озарение, Возврат времени (×2), Невидимая стена,
  Вселение души, Оживление тени, Воплощение.
- Сегментация эвристическая: вложенные условия выглядят соседними ветками; ручных правок пока нет.
- Гидра побеждается, только если за раунд рубить больше одной головы (одна отрастает каждый раунд).
- Сборка: код 71 КБ, библиотеки 97 КБ, данные отдельным чанком 808 КБ (160 КБ gzip). Можно ужать, если не
  хранить полный текст у параграфов с сегментами.
- В режиме живого ведущего у ведущего нет отдельного экрана: он видит текст на экране локации и правит вручную.
