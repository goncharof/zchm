# Заклятье Чёрного мага — в браузере

Браузерная версия первой постсоветской настольной ролевой игры (ЗАО «Камелот», Санкт-Петербург, 1997).
Движок ведёт механику по Инструкции, Книга Жизни читается как книга-игра. Сервер не нужен: статическая
сборка, сохранения в браузере, работает без сети и ставится на телефон как приложение.

## Что есть
- Партия из пяти классов (воин, варвар, вор, маг, жрец), уровни 0–12, лавка, трактиры, быстрый старт.
- Карта мира с дорогами и днями пути, случайные встречи из главы «Дорога».
- 15 локаций Книги Жизни, 647 параграфов. В 277 из них выделены ветки решений: исход открывается по выбору
  игроков, кнопки проверок удачи, боя, находок и платежей берутся из текста.
- Пошаговый бой по правилам: дистанция, инициатива, храбрость, особые атаки, бегство, стрелы и метательное оружие,
  союзники и спутники, магия монстров.
- 91 заклинание жреца и мага, большинство отыгрывается автоматически.
- Бестиарий на 97 статей с рисунками Олега Гвалии, 18 артефактов, Книга Сумерек как предыстория, справка по правилам.
- Финальная схватка с Чёрным магом.
- Режим ведущего: текст параграфов скрыт, чтобы его читал живой ведущий.

## Запуск
```bash
pnpm install
pnpm dev          # одиночная игра: http://localhost:5173
pnpm test         # тесты
pnpm build        # сборка в dist/
```

## Игра по сети и ИИ-ведущий
```bash
pnpm server                         # сервер на 8787; без ключей ходы ведёт сценарный ведущий (кнопки по книге)
GROQ_API_KEY=... pnpm server        # бесплатная облачная модель (также GEMINI_API_KEY, CEREBRAS_API_KEY, OPENROUTER_API_KEY)
ANTHROPIC_API_KEY=... pnpm server   # Claude (платно); ключи можно сочетать — модели пробуются по очереди
pnpm dev                            # в другом терминале; на главной — «Игра по сети»
```
Ключи удобнее положить в файл `.env.local` в корне проекта, по строке `GROQ_API_KEY=...` на ключ: сервер читает его
при запуске, в git и в Docker-образ файл не попадает.
Хозяин создаёт комнату и сообщает код, остальные входят по коду со своих устройств и берут героев.
Ведущий — ИИ, сценарный ведущий без ИИ, кто-то из игроков или никто. ИИ-ведущий читает Книгу Жизни, рассказывает,
озвучивает персонажей и сам бросает за проверки; если ни одна модель не отвечает, ход берёт сценарный ведущий —
он показывает сцену из книги и кнопки вариантов. Бои игроки ведут на экране боя.
Продакшен — один процесс: `pnpm build && pnpm build:server && pnpm start` или `docker build -t zchm . &&
docker run -p 8787:8787 -v zchm-data:/data -e ANTHROPIC_API_KEY=... zchm`.

Одиночную игру можно выложить на любой статический хостинг (`base: './'`), для GitHub Pages готов workflow
`.github/workflows/deploy.yml`. Сетевой игре нужен сервер (см. выше).

## Данные
JSON в `src/data/` генерируются из оцифрованной коробки скриптами в `tools/` (см. `CLAUDE.md`).
Исходные PDF в репозиторий не входят: `tools/fetch_sources.sh` скачивает их с zakoldovka.com.

## Документация для разработки
`CLAUDE.md` — точка входа; `docs/PROGRESS.md` — состояние и планы; `docs/DECISIONS.md` — решения и трактовки
правил; `docs/RULES.md` — конспект Инструкции; `docs/ARCHITECTURE.md` — устройство кода; `docs/SOURCES.md` — источники.
